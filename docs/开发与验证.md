# 开发与验证

本页记录校园网守护的实现边界与验证方法。下载安装和首次使用见 [README](../README.md)。

## 平台与实现

| 项目 | 说明 |
| --- | --- |
| 目标网络 | 武汉理工大学宿舍运营商网络 WHUT-ISP |
| 平台 | Windows 10 1607 及更新版本、Windows 11，x64 |
| 实现 | Rust + Win32 原生控件与 GDI，无浏览器或 WebView 常驻依赖 |
| 自启动 | 当前用户的 Windows `Run` 注册项，登录 Windows 后启动；可能受系统策略延迟 |
| 密码 | 当前 Windows 用户的凭据管理器；配置和日志不保存密码、Cookie 或令牌 |
| 安装目录 | 安装版默认 `%LOCALAPPDATA%\Programs\CampusNetworkGuardian`，无需管理员权限 |

程序不自动连接或切换 Wi-Fi，不修改系统代理，不处理运营商欠费或停机。设置保存一个必选、一个可选的校园网连接，每个连接分别记录网卡、网关和无线 SSID 等网络身份。账号、密码和 HTTP 同意适用于用户明确保存的连接。以前的单网卡配置可直接读取，需要守护第二个连接时再到设置中添加。

程序通过对应的网卡和源 IPv4 分别检查门户状态、登录和重拨。即使无线认证在线，以太网的认证失效也会独立处理。

两个连接能否保持同时在线取决于学校和运营商对该账号的在线会话限制。学校说明，超出接入区域的并发上限时，系统可能让最早上线的设备下线。参阅 [武汉理工大学校园网常见问题](https://nic.whut.edu.cn/jszc/202312/P020231227586313784356.pdf#page=5)。

程序通过 Native WLAN 读取 SSID。重连、IP 改变或 AP 漫游后，只要网卡、网关和 SSID 仍匹配，就可以重新确认当前源 IP 并继续守护。添加或认证无线连接时必须能读取 SSID，Windows 可能要求开启位置服务与桌面应用位置权限。参阅 [Microsoft 的 Wi-Fi 位置权限说明](https://learn.microsoft.com/en-us/windows/win32/nativewifi/wi-fi-access-location-changes)。

## WHUT-ISP 优先与有线兜底

设置中同时保存 WHUT-ISP 和以太网时，默认根据两个连接各自的门户状态选择 IPv4 出口。WHUT-ISP 可用时优先使用无线。无线失效且有线确认可用时切换到有线，无线确认恢复后切回。临时的检查失败可短时间沿用近期结果，两张网卡均无可用的确认结果时交回 Windows 按原路由选路。

Windows 比较默认路由的路由跃点数与接口跃点数之和。程序只调整两个已保存的物理连接已有的 IPv4 默认路由跃点数，IPv6、VPN、TUN 和其他接口的路由由 Windows 或对应软件管理。调用修改路由的 Windows API 需要管理员权限。以普通权限运行时，程序仍独立守护两张网卡的认证，并提示切换出口所需的权限。参阅 [Microsoft 的 SetIpForwardEntry2 说明](https://learn.microsoft.com/en-us/windows/win32/api/netioapi/nf-netioapi-setipforwardentry2)。

正常退出或更换保存的网络组合时，程序会恢复仍由自己管理的临时路由调整。程序异常终止时，临时调整可能继续存在。路由选择采用校园认证和运营商拨号状态，公网故障可能需要另外排查。

## 校园 Wi-Fi 随机 MAC 处理

v0.5.0 在无线认证前增加硬件地址检查：只处理已保存网络身份所对应的校园 Wi-Fi 配置，关闭其随机硬件地址，并核对当前 MAC 与永久硬件地址是否一致。当前地址未知、无法确认或仍不同，都不能继续发送认证凭据。有线连接不进入这条修改路径；旧配置格式兼容，不增加配置开关。

| 边界 | 行为 |
| --- | --- |
| 修改范围 | 指定无线接口上的实际连接配置；不把 SSID 直接当作配置名，不修改其他 Wi-Fi |
| 修改内容 | 仅关闭该配置的 MAC 随机化，不全局关闭、不写网卡 `NetworkAddress`，不伪造地址 |
| 生效确认 | 分别检查配置设置和当前有效地址；写入成功不代表当前 MAC 已改变 |
| 连接保持 | 不调用断开、重连或禁用网卡操作；必要时等待自然重连后再次确认 |
| 无法安全修改 | 权限不足、受组策略管理、存在无法安全保留的附加用户数据或无法识别的配置时，提示人工处理 |
| 错误处理 | 停止本次修改与认证提交，不通过提权、更改权限或扩大到全局设置来强行完成 |

Windows profile XML 可能包含 Wi-Fi 密钥材料，因此不请求明文密钥、不导出配置，也不把完整 XML 写入日志。Microsoft 明确说明 [`WlanSetProfile`](https://learn.microsoft.com/en-us/windows/win32/api/wlanapi/nf-wlanapi-wlansetprofile) 会清空 profile 的 custom user data；无法安全处理该附加数据时，应保留现状并要求人工操作。

系统对单网络随机硬件地址的修改通常在后续连接中体现；程序不强制重新连接，也不能保证 Windows 或驱动应用配置时完全没有连接波动。当前地址与永久地址仍不一致时保持等待或人工处理状态，不能据此去关闭全局随机化或修改驱动。参考 [Microsoft 的随机硬件地址说明](https://support.microsoft.com/en-us/windows/experience/connectivity-networking/connect-to-a-wi-fi-network-in-windows)。

关闭后的配置保留在 Windows 中，退出或卸载不恢复随机化；用户可在 Windows 的该网络属性中恢复。

MAC 稳定并不等于校园网一定在线，更不能证明 MAC 变化是所有认证失效的唯一原因；后续仍按门户的校园认证与运营商状态处理。

v0.5.1 本轮共 **112 项 Rust 测试通过**，2 项真实环境只读测试默认忽略。隔离回归包含 13 组 profile XML 测试和 8 项 MAC 状态/最终 POST 门禁测试，覆盖权限失败不反复写入、等待自然重连、配置读回、profile/MAC 变化后拦截登录与重拨、有线跳过 WLAN。另有等待期限与凭据缺失的回归；全部使用虚构配置及本地模拟服务，不调用实际 WLAN 写入。

## 认证入口与 NAS 识别

v0.5.1 修复了默认入口可能指向其他接入设备的问题。本次真实无线环境中，`/api/r/default` 返回 NAS `14`，而该无线连接实际截获的门户入口为 NAS `52`；两者返回本机 IP 一致，仍不能据此认定默认 NAS 正确。程序不硬编码这些编号，也不回退至默认入口。

| 阶段 | 约束 |
| --- | --- |
| 无凭据连通性探针 | 登录前请求 `http://www.msftconnecttest.com/connecttest.txt`；TCP socket 同时绑定所选接口与源 IPv4，不携带账号、密码、Cookie 或令牌 |
| DNS 与等待 | 使用系统解析器，仅选择有限个 IPv4 地址；调用方最多等待 DNS 结果 5 秒，超时停止本次入口发现。这不等于取消底层系统解析线程 |
| 校园重定向 | 只接受指向固定校园门户 `http://172.30.21.100` 的 302 跳转及允许的数值 NAS 路径；要求来源 IP 与本地 IP 一致，再核验最终登录页面的 IP 与 NAS |
| 参数校验 | 拒绝冲突、重复及无法识别的入口；仅对实际观察到的可选空字段 `wlanacname` 放行，不放宽 IP 与 NAS 校验 |
| 凭据请求 | 只提交到固定校园门户；每次 POST 写入前再次校验网络身份、路由与无线 MAC 条件 |
| 失败处理 | 无法确认入口时停止自动提交，提示人工检查；不因外网探针失败而重拨，不尝试默认 NAS |

该 Microsoft 地址的连通性检测用途见 [NCSI 官方排障文档](https://learn.microsoft.com/en-us/troubleshoot/windows-server/networking/troubleshoot-ncsi-guidance)。探针本身不需要认证凭据，程序不会向 Microsoft 发送保存的校园网账号密码。HTTP 重定向只能提供接入上下文，不能验证门户身份。

## 恢复策略

| 状态 | 处理方式 |
| --- | --- |
| 无线 MAC 检查未通过 | 等待自然重连或提示人工处理，不提交认证凭据 |
| 校园认证失效，网络身份匹配 | 尝试使用已保存的账号密码登录 |
| 校园认证在线，运营商明确拨号失败 | 尝试运营商重拨，无须主动退出校园账号 |
| 运营商拨号中 | 等待并查询结果 |
| 门户不可达、网络身份不匹配或状态不明 | 不盲目退出、登录或重拨 |
| 临时故障 | 按 15、30、60、120 秒退避，之后每 5 分钟重试 |
| 验证码 | 提示用户完成；认证上线后继续守护 |
| 账号、密码、强制改密或无法识别的登录结果 | 提示检查并重新保存设置，避免反复提交无效凭据 |

手动检查可以查询状态，但不会提前解除重试冷却。单次外网探测失败不作为重拨依据。打开认证页面使用学校通用入口，未必直接进入运营商状态页面。

学校当前门户使用 HTTP，程序无法验证门户身份或保护认证请求的传输。网络身份匹配不能消除 HTTP 的监听与篡改风险，详见 [安全说明](../SECURITY.md)。

## 版本检查与自动更新

v0.6.1 起，程序启动后短暂等待，再在后台检查版本。正常运行期间每 6 小时检查一次，自动更新触发的重启也等待 6 小时再检查。检查、下载或校验失败后等待 30 分钟重试。更新调度仅在程序运行期间有效。

程序仅接受比当前版本更新的稳定正式版。版本发现与文件下载使用 `gh-proxy.com` 镜像，安装前另行访问 GitHub 官方发布接口，确认候选版本和对应资产，并校验 GitHub 提供的 SHA-256。镜像可用性与官方接口可达性都影响更新。 [GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)

安装版使用当前用户的已注册安装目录静默升级。便携版在可写目录中原地更新名为 `campus-network-guardian.exe` 的程序。校验完成后，程序正常退出并释放临时路由，再由更新流程替换并重新启动守护。账号、网络配置和凭据存储独立于程序文件，升级沿用原有数据。

自动安装与重启使用普通用户权限。以管理员身份运行时，程序通过同一 Windows 用户的普通桌面会话交接，收到安装器的准备信号后正常退出。用户需要再次以管理员身份启动，才能恢复自动调整 IPv4 路由。镜像发布数据可能有缓存，更新检查可能晚于 GitHub 正式发布。

已运行的 v0.5.1 或更早版本无法自行获取更新功能，可从发布页手动升级至 v0.6.1。 [GitHub 最新正式版](https://github.com/Liunian520/campus-network-guardian/releases/latest)

## 构建

安装 Rust stable 的 Windows MSVC x64 工具链后执行：

```powershell
cargo fmt --all -- --check
cargo test --locked --all-targets
cargo build --release --locked --target x86_64-pc-windows-msvc
```

主程序位于 `target\x86_64-pc-windows-msvc\release\campus-network-guardian.exe`。项目为目标平台静态链接 C 运行库，成品无需额外安装 VC++ 运行库。

安装包使用 [Inno Setup 6.5+（6.x）](https://jrsoftware.org/isinfo.php) 编译：

```powershell
.\tools\build-installer.ps1 -IsccPath 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe'
```

产物在 `dist/`。脚本独立构建发布程序，只打包程序与许可证，不读取个人账号、凭据、配置或日志，也不运行安装器。静默安装可显式指定任务，例如：

```powershell
.\campus-network-guardian-0.6.1-windows-x64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /TASKS=autostart
```

开始菜单和安装完成页通过 `--show` 打开面板；已有实例时恢复原窗口。已配置后普通启动留在托盘。升级会正常退出同一安装位置的程序并保留配置；自启动状态遵循当前用户实际的 `Run` 项，显式安装任务参数除外。卸载只移除属于本安装路径的自启动项，保留被改为其他程序路径的同名项，默认保留用户配置与凭据。

## 模拟测试与 CI

常规测试使用模拟时钟、虚构凭据和仅监听 `127.0.0.1` 的模拟门户，覆盖认证失效、自动登录、重拨、超时、验证码和状态延迟，不读取已保存的密码、不修改自启动。NAS 发现回归模拟默认 NAS 与无线 NAS 不同、实际可选空字段、恶意重定向、IP/NAS 不匹配及重复或编码重复参数；测试构建的探针只允许注入的 loopback 地址，不解析或访问公网 Microsoft 地址。真实校园网只读检查被标记为忽略，不在常规测试或 CI 中运行。

GitHub Actions 的 Windows 检查运行 Rust 格式检查、锁定依赖的测试和界面对比度审计。Release 工作流编译安装包，并在一次性 GitHub 托管 Windows 环境中执行安装器冒烟测试：

| 验证项 | 检查内容 |
| --- | --- |
| 首次静默安装 | 版本、当前用户安装位置、开始菜单快捷方式、带引号的自启动路径；不自动启动应用 |
| 无配置界面启动 | 使用故意无效的虚构配置；确认账号密码为空、HTTP 同意未勾选、自启动复选框反映真实注册项 |
| 单实例和窗口恢复 | 第二次 `--show` 激活原实例，验证隐藏及最小化窗口恢复 |
| 运行中升级 | 正常退出匹配安装路径的应用，保留用户手动关闭的自启动偏好 |
| 自动更新交接 | 安装版与便携版静默替换旧版本，在原路径重启并保留用户配置。便携版只替换程序文件 |
| 卸载 | 删除本安装的程序、注册和快捷方式，保留虚构用户配置；保留指向其他位置的同名 `Run` 项 |

应用仅在没有有效网络配置、账号与 HTTP 同意的状态下启动；这条路径不读取凭据、不执行认证或重拨。安装器冒烟脚本限制为 GitHub 托管 Windows runner，不能用于测试个人电脑正在使用的安装。

手动运行 Release 工作流只上传构建产物；推送与 Cargo 版本一致的 `v主版本.次版本.修订版本` 标签，在所有检查通过后发布 GitHub Release。便携包只包含程序、README 和许可证声明，不包含个人数据或诊断日志。

## 界面与设计验证

界面参考 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 的 Fluent 2 条目和通用 UX 规则，适配 Rust / Win32。项目规范见 [MASTER.md](../design-system/campus-guardian/MASTER.md)，语义颜色集中于 [`src/ui_theme.rs`](../src/ui_theme.rs)。

```powershell
python tools/check-ui-contrast.py --self-test
python tools/check-ui-contrast.py
powershell -ExecutionPolicy Bypass -File tools\preview-ui.ps1 -Page all -Dpi 192
```

预览只使用虚构账号、网卡和状态，不启动守护线程、不读凭据、不改注册表。它截取离屏窗口，结束后清理自己的预览进程与托盘图标。预览用于检查 96 / 144 / 192 DPI；真实 Windows 独立“文本大小”设置与完整读屏器验证仍未完成。

| 预览参数 | 用途 |
| --- | --- |
| `-Status long-error` | 长状态提示、原生复制与滚动 |
| `-Status wifi-mac` | 固定 MAC 等待提示与完整状态文本 |
| `-WindowHeight`、`-ScrollBottom` | 短屏滚动和底部操作可达性 |
| `-LongAdapter -VerifyValidation` | 长虚构网卡名，校验错误、焦点与未保存草稿保留 |
| `-UnbrokenAdapter` | 无空格的长 ASCII 网卡名 |
| `-VerifyNavigation -WindowHeight 280 -Dpi 96` | 页面切换、Tab 顺序，以及焦点仍在账号框时主动滚动 |
| `-DiagnoseStatus` | 假状态控件行数与滚动条几何 |
| `-VerifyTrayActivation` | 托盘回调从隐藏、最小化和关闭到托盘状态恢复窗口 |
| `-VerifyAuthor` | 作者与关于入口的原生可访问名称、Tab 支持及客户区内完整可见性；不打开外部链接或模态框 |

表单校验在凭据与注册表写入之前返回；验证期间检查真实原生控件内容，密码草稿仅检查长度。托盘测试使用禁用的离屏预览窗口，不自动操作真实鼠标或通知区域。这些界面检查不等于真实断线恢复验证。
